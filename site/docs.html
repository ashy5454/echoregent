Integration Guide

EchoRegent sits between your application and any LLM. Three integration paths: OpenAI-compatible proxy (recommended), native MCP server, or direct REST API.

Quick Start

The fastest path: change one URL in your existing OpenAI client. Your code stays exactly the same — EchoRegent intercepts, classifies, compresses, and forwards to your LLM.

Step 1 — Get your API key

Request a free key at echoregent.ai/pricing. It arrives by email within 60 seconds.

Step 2 — Point your client at EchoRegent

JavaScript / TypeScript
import OpenAI from 'openai'

const client = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,       // your existing LLM key
  baseURL: 'https://api.echoregent.ai/v1',
  defaultHeaders: {
    'x-cts-key': process.env.ECHOREGENT_KEY, // your EchoRegent key
  }
})

// Everything else stays identical
const response = await client.chat.completions.create({
  model: 'gpt-4o',
  messages: conversationHistory  // EchoRegent compresses this automatically
})
Python
from openai import OpenAI

client = OpenAI(

Authentication

EchoRegent uses two separate keys: your EchoRegent key for billing and rate limiting, and your LLM provider key which is forwarded to the upstream model.

HeaderValuePurpose
x-cts-keyYour EchoRegent API keyBilling, rate limit, quota
x-llm-keyYour LLM provider key (OpenAI, etc.)Forwarded to upstream model
x-llm-provideropenai · anthropic · geminiWhich provider to route to

When using the OpenAI-compatible proxy, your LLM key is passed as Authorization: Bearer sk-... and EchoRegent forwards it transparently to the upstream model. It is never stored.

OpenAI Proxy

The recommended integration. EchoRegent exposes a fully OpenAI-compatible /v1/chat/completions endpoint. Change your baseURL — nothing else changes in your codebase.

POST/v1/chat/completions

EchoRegent intercepts the request, runs the classify + compress pipeline on messages, then forwards the compressed payload to your upstream model. The response you receive is identical to what your LLM returns — EchoRegent adds its headers and steps aside.

Supported providers via proxy

  • OpenAI (GPT-4o, GPT-4o-mini, o1, o3)
  • Anthropic (Claude 3.5, Claude Sonnet 4.6)
  • Google (Gemini 2.0 Flash, Gemini 1.5 Pro)
  • Mistral, Groq, Together, or any OpenAI-compatible endpoint

Specifying a non-OpenAI provider

Route to Anthropic via proxy
const client = new OpenAI({
  apiKey: process.env.ANTHROPIC_KEY,
  baseURL: 'https://api.echoregent.ai/v1',
  defaultHeaders: {
    'x-cts-key':       process.env.ECHOREGENT_KEY,
    'x-llm-provider':  'anthropic',
  }
})

MCP Server

EchoRegent ships a native MCP (Model Context Protocol) server. Four tools are available immediately — compress, classify, remember, and recall. Works with Claude Desktop, Cursor, Windsurf, and any MCP client.

Cursor Setup

Add to your ~/.cursor/mcp.json:

~/.cursor/mcp.json
{
  "mcpServers": {
    "echoregent": {
      "url": "https://api.echoregent.ai/mcp",
      "headers": {
        "x-cts-key": "your-echoregent-key"
      }
    }
  }
}

Claude Desktop Setup

claude_desktop_config.json
{
  "mcpServers": {
    "echoregent": {
      "command": "npx",
      "args": ["-y", "@echoregent/mcp-server"],
      "env": { "ECHOREGENT_KEY": "your-key" }
    }
  }
}

Direct API

Call EchoRegent directly without going through the proxy. Useful when you want to pre-process context before assembling your LLM request.

POST /compress

POSThttps://api.echoregent.ai/compress

Requires Authorization: Bearer <your-echoregent-key> header.

Request body
{
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ],
  "options": {
    "maxTokens": 4096,       // optional target window
    "preserveLast": 2        // always keep last N turns uncompressed
  }
}
Response
{
  "compressed": [ /* compressed messages array */ ],
  "domain": "coding",
  "intent": "debugging",
  "tokensSaved": 1842,
  "compressionPct": 67,
  "protected": false,
  "cacheHit": false
}

POST /v1/chat/completions

POSThttps://api.echoregent.ai/v1/chat/completions

Fully OpenAI-compatible. Accepts the exact same body as openai.chat.completions.create(). EchoRegent compresses the messages field, then forwards to your upstream model. Returns the upstream response unmodified plus EchoRegent headers.

Additional headers required:

  • x-cts-key — your EchoRegent key
  • x-llm-key — your upstream LLM API key (optional if using Authorization: Bearer)
  • x-llm-provider — openai (default) · anthropic · gemini

Response Headers

HeaderTypeDescription
x-cts-tokens-savedintegerTokens removed from context
x-cts-compression-pctinteger 0–100% reduction in context length
x-cts-domainstringDetected conversation domain
x-cts-intentstringDetected intent
x-cts-cache-hitbooleanWhether response came from semantic cache
x-cts-protectedbooleanTrue if compression was disabled (medical/legal/crisis)

Protected Zones

Three conversation types are architecturally protected from compression:

Protected — compression disabled

When the classifier detects one of these domains, the compression step is skipped entirely. The full context is forwarded. These zones cannot be overridden by API callers.

MEDICAL LEGAL CRISIS

Protected conversations return x-cts-protected: true and are not counted toward your quota.

Windsurf Setup

Add to your Windsurf MCP configuration file at ~/.windsurf/mcp_config.json:

~/.windsurf/mcp_config.json
{
  "servers": {
    "echoregent": {
      "serverUrl": "https://api.echoregent.ai/mcp",
      "auth": {
        "type": "header",
        "header": "x-cts-key",
        "value": "your-echoregent-key"
      }
    }
  }
}
