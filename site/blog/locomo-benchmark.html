We beat mem0 by 26× on
their own benchmark.

By the EchoRegent team · June 2024 · 8 min read

EchoRegent uses 259 tokens per query on LoCoMo. mem0 publishes 6,956 as their figure on the same benchmark. That's a 26.8× difference. Here's how we did it, why it matters, and what the tradeoffs are.

What is LoCoMo?

LoCoMo (Long-term Conversational Memory) is a benchmark for evaluating how well AI memory systems retain and retrieve information from long conversations. It simulates realistic multi-session conversations where a user and an AI discuss various topics over time, then asks factual questions about what was discussed.

mem0 chose LoCoMo for their published evaluation. We ran the same test. The question is simple: how many tokens does your memory system need to hold per query while still answering correctly?

How EchoRegent achieves 259 tokens

EchoRegent's approach is different from mem0's in one fundamental way: instead of extracting and storing structured facts from conversations, we compress the conversational history directly using T5, a sequence-to-sequence transformer fine-tuned for summarisation.

The pipeline per request:

  1. Classify — DistilBERT reads the conversation and returns domain, intent, risk, state in <10ms
  2. Cache check — MiniLM checks whether a semantically similar conversation was recently compressed
  3. Compress — T5 summarises the history using a domain-specific strategy, preserving the last 2 turns uncompressed
  4. Forward — the compressed context is sent to your LLM

Why F1 is higher despite using fewer tokens

This surprised us too. EchoRegent achieves F1 0.079 vs the full-context baseline of 0.069 — while using 98.6% fewer tokens than full context.

Our interpretation: long conversations contain significant noise — filler turns, re-explanations, hedging, pleasantries. When T5 compresses these away, the signal-to-noise ratio of the context sent to the LLM actually improves. The LLM produces more accurate answers from compressed context than from the noisy full history.

What about quality vs mem0 directly?

mem0 measures quality via LLM-as-judge on a 0–100 scale. We measure F1 via token-overlap on LoCoMo QA pairs. These are not directly comparable metrics. We're not claiming EchoRegent produces better answers than mem0 — we're claiming it uses 26.8× fewer tokens on the same benchmark dataset. The efficiency claim is solid; direct quality comparison would require a shared evaluation protocol.

The tradeoffs

mem0 extracts structured facts and stores them in a graph. This has advantages: facts are explicit, queryable, and don't lose information through compression. If you need to retrieve "what did the user say their dog's name was 3 weeks ago," a fact graph answers that more reliably.

EchoRegent's compression is better for latency-sensitive applications where the conversation history is recent (within a session), and where conversational noise is high. It's not a replacement for long-term fact storage — it's a complement.
